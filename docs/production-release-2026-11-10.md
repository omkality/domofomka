# Первый выпуск v2.0.0 на prod

Владелец разрешил переключение 10 ноября 2026 года. [PR #9](https://github.com/omkality/domofomka/pull/9)
слит в master, рабочая ревизия — `ddf86d5e1294a90a9ca470087515f40b0dbf50b7`.
[Ручной prod-workflow](https://github.com/omkality/domofomka/actions/runs/42719817890) завершился успешно:
проверки, сборка, аудит зависимостей, публикация и развёртывание готовых образов по digest.

## Переключение

До изменения серверного `.env` опубликованный bootstrap проверил все 23 файла v1.5.6 и сохранил
исходники, окружение и прежние образы для отката. Redis оставлен; его данные не удалялись.
Установлен ограниченный ключ приёмника и отдельные секреты GitHub Environment `prod`.
Разрешение Environment подтверждено после подготовки данных; SSH, root/password и Amnezia не менялись.

PostgreSQL запущен с лимитом 192 МиБ, закрытым портом и ограниченными WAL, временными файлами и логами.
Каталог и пустая очередь prod созданы отдельно от dev. Тестовые задания не переносились.
Принятый дамп проверен по SHA-256 `b37c9b12878b939024d70cdafc97710a7386e570b20c4db3a4a050ffdd375c4e`.
Ревизия каталога — `9d79c9fed085ef3c289d660c5fa5dbbb1d5639943b67aeed1618892e34c8ec0a`.
После восстановления сверены количества всех таблиц: 105 253 дома с кодами, 1 001 685 кодовых записей,
1 008 682 записи происхождения. Каталог с индексами занимает около 1,0 ГиБ.
Права роли API и 18 действующих индексов проверены. Сама роль не может менять каталог.
Исходная `codes.db` не изменена; индекс v1 проверен по SHA-256 и исходной БД, подключён только для чтения.

Actions остановил прежний процесс бота перед заменой приложений, проверил v2 без fallback,
получение дома и блокировку действующего runtime. Оба образа имеют ожидаемую ревизию,
работают с UID/GID 10001 и read-only корнем; исходники хоста в них не подмонтированы.

## Проверки после переключения

- Все 113 контрольных запросов дали те же статусы, адреса и варианты v1/v2, что принятый dev.
  Три отдельных проверки полных ответов, включая коды, также совпали с эталоном.
- Геопоиск v2 через настроенный РФ-прокси вернул ожидаемый адрес за 0,33 с;
  следующий текстовый запрос вернул тот же адрес за 0,002 с. Это отдельные измерения, не SLA.
- VK доступен через настроенный прокси и напрямую. При искусственно недоступном прокси
  отдельный проверочный процесс перешёл напрямую и успешно прочитал сервер Long Poll.
- DaData доступна через настроенный РФ-прокси. Прямое подключение с Финляндии дважды
  закончилось `ConnectTimeout` при штатном лимите подключения 2 с. При недоступном прокси
  попытка прямого fallback выполнена и закончилась тем же таймаутом. Это ограничение внешнего
  маршрута; переход напрямую не гарантирует доступность провайдера. Конфигурация работающего API
  не менялась этими пробами; недоступность геокодирования обрабатывается отдельно от текстового поиска.
- API и PostgreSQL здоровы, у трёх контейнеров нет OOM и перезапусков.
  После первой сверки истории: 220 завершённых входящих записей и один завершённый исходящий ответ;
  незавершённых и ошибочных задач в момент проверки нет.
- После проверок приложения занимали около 137/63/71 МиБ (API/бот/PostgreSQL),
  доступно около 350 МиБ памяти и 28,5 ГиБ диска. Таймер защиты диска активен.

Проверки prod читали HTTP API, VK и DaData; отдельные тестовые сообщения пользователям не отправлялись.
Доставка ответа, показ кодов и кнопки ранее проверены владельцем в настоящем dev-диалоге.
Новое оформление prod проверяется тем же уже принятым кодом; приёмка не объявляет его универсальной точностью поиска.

## Дальнейшие выпуски и откат

`PROD_DEPLOY_ENABLED=true`, но push master сам по себе не разворачивает prod: необходим ручной запуск
на master и подтверждение Environment. Dev продолжает развёртываться автоматически.
Для аварийного возврата первого выпуска сохранён `legacy-v1` в workflow `Rollback application`.
PostgreSQL и принятый каталог при откате не удаляются. [Ограничения повторного переключения](release-v2.md#откат-первого-выпуска).
Регулярные копии на ПК и внешние оповещения не добавлены.
