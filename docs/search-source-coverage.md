# Исходные варианты адресов и сохранность кодов

Продолжение [разбора 7 ноября](search-coverage.md). Изменения предназначены только для dev.
Master/prod, исходная SQLite v1 и содержимое каталога не меняются. Рабочий поиск использует PostgreSQL;
native OpenSearch остаётся локальным кандидатом.

## Почему адрес совпадал, а часть кодов пропадала

После отбора кандидатов каталог предпочитал короткое полное название населённого пункта.
Допустимый исходный вариант с дополнительной административной частью мог исчезнуть вместе со своими кодами.
Ещё один случай — подтверждённый вариант с родительским населённым пунктом: исходная строка
«Москва, Щербинка» относится к тому же подтверждённому дому, но его основное поле города — «Щербинка».
Совпадения только основного названия было недостаточно для сохранения варианта в выдаче.

Теперь сопоставляются пары «населённый пункт, улица» из существующих исходных вариантов.
Не создаётся произвольное сочетание города одного варианта и улицы другого.
Короткий официальный адрес не отбрасывает другой подходящий вариант с кодами только из-за
дополнительных административных слов. При нескольких разных ID бот предлагает выбор.
В выдаче v2 коды разных неподтверждённых домов не объединяются в одном ответе.

Новых колонок, миграции и перепривязки кодов нет. Дополнительные сведения о вариантах используются
только в памяти читателя и берутся из уже существующих полей `aliases`/`alias_search`.

## Границы полного имени

Совпадение исходного варианта не разрешает преждевременно завершать поиск. Если оно объясняет
разорванное слово, должны быть проверены и кандидаты после его склейки. Это проверено отдельным
примером с двумя подходящими населёнными пунктами и различными кодами.

Слово может быть служебным в свободном запросе и частью сохранённого названия улицы.
После его удаления короткое имя не должно становиться полным. Такое слово требуется в адресной
части исходного запроса. Например, название со словом «Посёлок» нельзя считать полностью указанным,
если этого слова в запросе нет. Короткий запрос сохраняет выбор; полный может выбрать нужную улицу.
Проверка не содержит исключений с названиями конкретных улиц.

Буквы, корпуса, строения, диапазоны и номера улиц остаются точными ограничениями.
Резерв v1 не разрешает вернуть дом другого номера ради увеличения числа находок.

## Отказ каталога и безопасный fallback

При локальной имитации полного отказа каталога обнаружено смешение исходных групп внутри v1:
общий заголовок ответа соответствовал запросу, но часть кодов принадлежала другому номеру дома.
Проверки только заголовка недостаточно. В воспроизведённом случае старый ответ содержал 10 уникальных
кодов, из которых 6 относились к запрошенному дому.

Теперь fallback v2 проверяет каждую исходную группу до чтения её кодов. Учитываются дом с буквами,
корпусами и строениями, номера улиц, значимые слова и явно указанный населённый пункт. При защите
известной улицы сохраняется требование полного совпадения населённого пункта и улицы. Похожие
названия двух разных городов не считаются одним городом по подстроке. Старые непрозрачные поля
дома проверяются без их принудительной перепривязки к официальному адресу.

Прямой REST v1 вызывает прежний поиск без дополнительного фильтра. Его порядок, повторы и правила
совместимости сохраняются. Опциональный фильтр включается только маршрутом v2, одинаково для
вспомогательного индекса и чтения исходной SQLite. Каталог и источник кодов не изменяются.

После исправления имитация отказа возвращает те же 6 кодов запрошенного дома; прямой v1 по-прежнему
возвращает 10. Сбой вводится только в локальном тестовом процессе, без остановки PostgreSQL на VDS.
Лабораторный replay сохраняет выбранные правила fallback, а аудитор кодов применяет именно их:
старые снимки сравниваются со старым v1, новые — с фильтрацией каждой исходной группы.

## Перепутанные поля и официальный адрес без кодов

У каталога и лабораторного native теперь одна проверка исходных полей. Неподтверждённая запись,
в поле города которой находится улица, не становится уверенным адресом v2. Сокращение «ул.»
учитывается так же, как полное слово. В этом случае сохраняется допустимый резерв v1.

Отсутствие отдельного GUID само по себе не означает ошибку данных. Известный дом без кодов
может быть восстановлен из упакованного ГАР и иметь ID `address:…`. Он исключён из проверки
перепутанных исходных полей. Это проверено и на настоящем PostgreSQL с упакованным адресом,
где слово «Улица» входит в название населённого пункта.

## С чем сравниваются коды

Аудит сравнивает уникальные кортежи «подъезд, источник, код» с двумя независимыми основаниями:
фактическим ответом v1 и замороженным предыдущим результатом v2. Одинаковое количество кодов
не считается их равенством. Для меню учитываются наборы, доступные через отдельные варианты;
это не автоматическая отправка всех этих кодов пользователю.

```powershell
python -m tools.audit_search_code_coverage `
  --results artifacts/private/before artifacts/private/after `
  --baseline before/catalog `
  --catalog artifacts/search/frozen-serving.db `
  --output artifacts/private/code-comparison --workers 8
```

Снимок данных у сравниваемых запусков должен совпадать. Аудитор проверяет ревизию каталога,
наличие основания для каждого текста и одинаковый набор кодов основания при повторе текста.
Сырые запросы, ответы и происхождение остаются в `artifacts/private`, агрегаты — в
[JSON](search-source-coverage-summary.json).

## Что считается исправлением, а не потерей

Старый v1 иногда смешивал разные города, переставлял номер улицы и дома, принимал один номер
за другой после удаления дефиса либо выбирал адрес по одной строке цифр. Такие коды не восстанавливаются.
Регистр, похожесть и совпавший номер дома не доказывают идентичность адреса.

Отдельно проверены 12 исходных групп, исключённых более ранней защитой полного названия:
все доступны со своими кодами по полным исходным формулировкам. Их ID и данные сохраняются.
Уточнения в скобках, дополнительные слова названия и неподтверждённые варианты города не сливаются
с официальным домом без проверки происхождения.

## Измерения и оставшиеся условия

Окончательный код этого цикла: `57bdadc`, `6eca1eb`, `483a33a`, `389700f`; аудитор —
`4fb63f1` и уточнение правил fallback в `483a33a`. Полный набор — 46 908 записей,
два маршрута и 93 816 ответов. Исходники всех восьми процессов и снимок данных совпадают.
Ошибок движка и конфликтов 297 ручных ограничений нет.

| Маршрут | Историческая подсказка, из 44 083 | Подсказка исправления, из 2 528 |
| --- | ---: | ---: |
| PostgreSQL-каталог и проверенный v1 | 43 992 | 1 395 |
| Локальный native с индексом улиц с кодами, каталог и проверенный v1 | 43 992 | 1 615 |

Предыдущий кандидат сохранял 44 002 исторические подсказки и 1 396 подсказок исправления у каталога.
Новая проверка fallback отклонила **11 разных текстов с сокращёнными городами**:
10 исторических и одну гипотезу исправления. Слитные и разорванные слова, числовые формы вроде
«26ти» и старые кварталы с отдельным корпусом сохранены. Сокращение города нельзя безусловно
считать другим городом, но и совпадение префикса нельзя приравнивать к полному названию.
Эти 11 случаев — **незакрытая регрессия совместимости**, а не доказанное исправление пользовательского
намерения. До выпуска нужно поддержать уточнение или безопасный поиск префикса в v2.
Прямой v1 не менялся. Пилот этих случаев не содержал, поэтому не заменяет полный прогон.

Коды проверены на 41 918 разных текстах, соответствующих 44 083 историческим записям.
При сохранённом адресе число отличий кодов v1 уменьшилось со 178 до 2: в 176 случаях
восстановлена доступность полного старого набора через выбор исходных вариантов.
Оставшиеся два — исключение другой нумерованной улицы с другим домом и отдельный неподтверждённый
вариант города с цифровым суффиксом. Последний доступен по исходной формулировке через v1;
его код не приписывается официальному дому без доказательства.

Относительно предыдущего v2 у каталога расширились наборы в 183 случаях и сузились в 11.
Из них один — другая официальная улица при полном названии, десять — описанная регрессия
с префиксом города. Относительно фактического v1 остаётся 17 отличий: шесть нарушали явные
ограничения адреса, одно связано с неподтверждённым вариантом, десять — с префиксами.

У native относительно предыдущего каталога сузились наборы в 33 случаях: десять новых префиксов
и 23 прежних различия названий. Среди прежних в семи исключены другие полные официальные имена,
в семнадцати — более длинные неподтверждённые имена; один случай входит в обе категории.
Это классификация различий, не доказательство намерения пользователя. Политика выбора
неполных запросов остаётся отдельным условием приёмки native.

В расширенном пилоте из 1 615 записей сохранены 500/500 исторических и 65/65 подсказок прежних
потерь. В 399 ограничениях адреса конфликтов нет. На 453 предполагаемых опечатках — 381 подсказка
у каталога и 452 у native. Из 32 наблюдаемых последующих уточнений native предлагает коды в 32
случаях, каталог — в 9; в 193 контекстных проверках нет конфликтов или другого автоматического
адреса относительно наблюдаемого уточнения. Страты пересекаются и не складываются.

400 полных ответов рабочего PostgreSQL-клиента совпали с файловым артефактом при выключенном кеше.
В последнем локальном парном измерении медиана PostgreSQL — 8,355 мс, 95-й процентиль — 39,362 мс,
без HTTP и VK, одновременно с лабораторным прогоном. Это не SLA и не замер сети VDS.
Полный локальный набор: 667 проверок прошли, 2 пропущены. CI Linux: 668 прошли, 1 пропущена.

## Проверка Германии

GitHub Actions развернул `389700f` по digest. У API и бота нет исходников, подмонтированных с хоста;
PostgreSQL/очередь не перезапускались. OOM, незавершённой транзакции и оставленных данных входа
в registry при проверке не было. Проверка отправки и редактирования на dev-боте использовала
только владельца: обе операции приняты VK, связь запроса с нажатием и запись аналитики подтверждены.
Массовой отправки сообщений не было.

Из 30 HTTP-запросов в 28 совпал полный ответ. В двух широких запросах совпали адресный результат
и коды, но отличается причина fallback: PostgreSQL VDS завершил работу по `QueryCanceled`, а
локальный каталог вернул `not_found`. Время HTTP составило около 2,9 и 2,5 секунды. Это отдельная
незакрытая проверка стоимости широких запросов, а не сетевой сбой VK. Ответы всех четырёх
дополнительно выбранных домов совпали полностью. Эти HTTP-пробы не отправляют сообщения VK.

Историческая подсказка — проверка совместимости, не истина о намерении пользователя.
Частичные и заменённые прогоны не используются как подтверждение окончательного кода.
Содержание каталога сохраняет ревизию
`9d79c9fed085ef3c289d660c5fa5dbbb1d5639943b67aeed1618892e34c8ec0a`.
Схема БД и [порядок развёртывания](operations.md) не изменились.

Ресурсное условие native не закрыто. Дополнительный локальный опыт с C1 и heap 96 МиБ при лимите
192 МиБ упёрся в лимит памяти и не получил рабочего HTTP-ответа; процесс при измерении ещё работал,
OOM-kill не зафиксирован. Контейнер остановлен. На VDS OpenSearch не устанавливался;
VPN и другие службы для освобождения памяти не менялись.

Следующие условия #10: сокращённые города, стоимость широких запросов, выбор по неполным именам
и размещение native. По сообщению владельца основная аудитория — Москва, Подмосковье и Петербург:
нужен отдельный разрез качества этих регионов. Популярность может влиять на порядок допустимых
вариантов после проверки; она не заменяет явно указанный город, дом, корпус или букву.
Переход в master/prod не выполняется.
