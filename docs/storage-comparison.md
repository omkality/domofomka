# Сравнение SQLite и PostgreSQL для v2

Проверка выполнена локально 06.11.2026. На этом этапе Германия продолжает читать SQLite,
а PostgreSQL проверяется как замена нормализованного рабочего каталога. Прод не меняется.
SQLite выбран для первого развёртывания из-за простоты и малого расхода ресурсов, а не как окончательное хранилище.

## Что сравнивали

Одинаковые адреса, коды, ранжирование v2 и fallback v1. Кеш результатов выключен.
Каждый запрос поочерёдно выполнялся через оба хранилища; порядок чередовался.
Сравнивались полные ответы, включая коды и варианты адресов.

Тест работал в Linux-контейнерах: PostgreSQL ограничен одним CPU и 192 МиБ памяти,
процесс поиска — одним CPU и 384 МиБ. SQLite-файлы находились внутри Linux,
чтобы не приписывать задержки файловой системы Windows самой SQLite.
PostgreSQL использовал постоянное соединение только для чтения.

| Проверка | SQLite | PostgreSQL |
| --- | ---: | ---: |
| Совпадение полных ответов на 46 611 запросах | 46 611 | 46 611 |
| Медиана одного поиска | 3,548 мс | 2,037 мс |
| p95 одного поиска | 52,443 мс | 8,728 мс |
| Рабочие данные с индексами | 824 635 392 байта | 1 096 824 499 байт |

В PostgreSQL дополнительно находятся 1 008 682 записи происхождения кодов;
рабочая SQLite-копия их не содержит. Поэтому размеры не являются сравнением одинакового состава таблиц.
Для полнотекстового поиска PostgreSQL использован GIN по простому словарю и отдельный частичный GIN
для улиц с кодами. Без частичного индекса запросы к распространённым названиям были заметно медленнее.

В обеих копиях 107 811 домов с кодами, 1 001 908 уникальных кодов, 111 861 вариант исходного адреса
и 1 077 070 документов улиц. Это замороженный набор до следующего исправления муниципальных формулировок.
PostgreSQL сохранил сжатые наборы известных номеров домов: 34,8 млн домов не разворачивались
в отдельные строки PostgreSQL в этом эксперименте.

## Ограничения результата

Это повторная обработка корпуса из выгруженных диалогов, а не доказательство правильного понимания каждого запроса.
Полное совпадение подтверждает сохранность поведения при замене хранилища.
Качество поиска проверяется отдельно на ручной разметке и отрицательных примерах.

Замеры не включают VK, DaData, сеть между серверами и ожидание очереди.
Словари и кеш операционной системы уже могли быть прогреты; настоящий запуск с холодным кешем ОС не измерялся.
Рядом выполнялись другие локальные работы. Эти числа не являются обещанием задержки на VDS.
После полного прогона PostgreSQL занимал около 119 МиБ памяти при лимите 192 МиБ и не был завершён по OOM.

## Решение для следующей проверки

Результаты позволяют продолжить проверку v2 на существующем PostgreSQL без отдельного сервиса OpenSearch.
Предпочтение — одному нормализованному источнику кодов в PostgreSQL, если совместная работа с очередью
укладывается в память и диск немецкого dev-сервера. В эксперименте уже есть связи дом → подъезд → код,
справочник источников и сохранённое происхождение каждой исходной строки.

До переключения нужны проверка совместной нагрузки с очередью, ограниченные соединения и таймауты,
восстановление резервной копии и запас диска для безопасного отката.
На Германии около 1,3 ГиБ свободного места: просто добавлять гигабайтную базу рядом с прежней копией опасно.
Исходная SQLite для v1 сохраняется как снимок совместимости; это отдельная задача от замены каталога v2.

## Воспроизведение

Инструменты `tools/postgres_catalog_experiment.py`, `tools/postgres_search_experiment.py`
и `tools/compare_postgres_catalog.py` не подключены к рабочему API.
Загрузчик допускает только локальную БД с именем, начинающимся на `domofomka_catalog_bench`,
через `CATALOG_BENCHMARK_DSN` и отказывается перезаписывать уже загруженные данные.

Для загрузки используется `python -m tools.postgres_catalog_experiment`.
Для полного сравнения — `python -m tools.compare_postgres_catalog --limit 0 --output <новая-папка>`.
Пути к каталогу, исходной базе, индексу v1 и закрытому корпусу задаются аргументами этих инструментов.
Выгрузки сообщений и подробные ответы остаются в игнорируемой папке `artifacts/private`.
