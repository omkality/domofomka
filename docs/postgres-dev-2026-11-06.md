# PostgreSQL на dev — проверка 06.11.2026

Изменены dev и тестовый бот на Германии. Master и прод в Финляндии не изменялись.
[Схема БД](database.md) показывает реальные таблицы, поля и связи.

## Данные

В отдельной БД существующего PostgreSQL находятся 107 646 домов с кодами,
1 001 838 уникальных кодов, 111 861 вариант адреса и 1 008 682 строки provenance.
Внешних ключей — семь. Поисковый слой содержит 1 076 957 документов улиц и столько же сжатых наборов домов.
Полный ГАР не разворачивался на VDS в десятки миллионов отдельных строк PostgreSQL.
Размер БД после восстановления — 1 073 845 939 байт.

Потоково сверены все строки кодов и provenance: число строк и SHA-256 упорядоченного содержимого
совпали у исходного каталога, восстановленной локальной БД и работающей БД Германии.
Проверка включает сами коды, подъезды, источники и привязки к домам.
Закрытые сводки остаются в `artifacts/private/postgres-migration/`.

Исходная `codes.db` не изменена: v1 сохраняет прежний поиск, порядок и дубли.
Рабочий SQLite-каталог v2 с VDS удалён. SQLite остаётся локальным промежуточным форматом подготовки данных.

## Ограничения

| Параметр | Значение Германии |
| --- | ---: |
| Процессы API / соединения читателя на процесс | 1 / 1 |
| Лимит соединений роли читателя | 2 |
| RAM PostgreSQL / API / бота | 192 / 384 / 128 МиБ |
| shared_buffers / work_mem / maintenance_work_mem | 32 / 2 / 16 МиБ |
| max_wal_size / min_wal_size | 64 / 32 МБ |
| temp_file_limit | 128 МБ на процесс |
| CATALOG_CONNECT_TIMEOUT_SECONDS | 3 с |
| CATALOG_STATEMENT_TIMEOUT_MS | 2 000 мс |
| CATALOG_LOCK_TIMEOUT_SECONDS | 2 с |
| CATALOG_OPERATION_TIMEOUT_SECONDS | 5 с |

Настройки находятся в `.env`. Соединение используется повторно, внутренние потоки сериализуют чтение.
Клиентский дедлайн ограничивает ожидание ответа драйвера, а не только серверное исполнение SQL.
Установление соединения имеет отдельный таймаут. Эти значения не задают полное время VK, v1 и очереди.
После ошибки соединение закрывается; следующий запрос может подключиться заново.

Роль API имеет только CONNECT, USAGE и SELECT. Проверен отказ UPDATE даже после выключения
read-only настройки отдельной тестовой сессии: действуют ограничения прав.
Административные параметры очереди и токен VK очищены из окружения API.
Ревизия каталога входит в кеш и диагностику; клиент проверяет версию схемы и готовность сборки.

## Результаты

- 257 тестов с настоящим PostgreSQL прошли; одна архивная проверка старого цикла пропущена.
- Все 46 611 полных ответов рабочего PostgreSQL-клиента совпали с актуальным SQLite.
  Это сохранность поведения, а не доказательство намерения каждого пользователя.
- В чередующемся локальном сравнении без кеша p50/p95 SQLite — 3,667/56,676 мс,
  PostgreSQL — 2,044/9,381 мс. Рядом выполнялись другие работы; это не обещание задержки VDS.
- На Германии временно запрещены подключения только роли каталога и завершена её сессия.
  Настоящий HTTP-запрос получил коды через настоящий v1, endpoint выбранного дома вернул 503.
  После восстановления лимита тот же текст получил результат v2. БД очереди не отключалась.
- Через VK SDK владельцу тестового бота отправлен ответ на длинный адрес;
  программно созданное нажатие подъезда отредактировало то же сообщение.
  Диагностика сохранила `storage_backend=postgres` и связь с исходным запросом.
  Отдельно отправлен известный дом без кодов с явным сообщением и без кнопок подъездов.
  Это синтетические события и подтверждения VK, а не реальные клики или подтверждение прочтения.

Отдельные HTTP-вызовы VDS заняли около 472 мс для первого точного запроса,
770 мс для длинного адреса, 31 мс для известного дома без кодов и 1 мс при попадании в кеш.
Отказ каталога с успешным v1 занял 742 мс; после восстановления — 25 мс на v2.
VK и ожидание очереди в эти числа не входят.

## Совместная нагрузка

Два HTTP-клиента выполнили 60 запросов v2 с разными ключами кеша.
Одновременно выполнены 40 SQL-циклов inbox/outbox с диагностикой, без обращений к провайдерам.

| Операция | p50 | p95 | Максимум |
| --- | ---: | ---: | ---: |
| HTTP v2 | 29,668 мс | 65,304 мс | 80,816 мс |
| Цикл очереди с диагностикой | 192,767 мс | 537,436 мс | 551,162 мс |

Ошибок HTTP не было, все ответы использовали v2, все 40 циклов завершились и записали диагностику.
Тестовые строки удалены из обычной статистики. Это небольшой профиль VDS, а не длительное нагрузочное испытание.

## Перенос и резервные копии

Перед переключением проверены копия исходников/настроек, восстановление очереди и текущий SQLite-снимок.
Дамп подан через SSH прямо в pg_restore без промежуточного файла на VDS.
Загрузка контролировала свободное место и должна была остановиться на резерве 256 МиБ.
Минимум свободного места — 335 634 432 байта, около 320 МиБ.
Счётчики реальных заданий совпали до и после переноса; последовательности не сбрасывались.

При публикации подготовлен и проверен независимый дамп каталога вне VDS.
После сверки полного содержимого работающей БД временные локальные снимки каталога удалены ради запаса диска.
На VDS оставлен манифест offsite-копии; неизменяемый каталог не копируется ежедневно.
Очередь с новыми событиями резервируется ежедневно отдельно; после переноса повторно проверено её восстановление.
Автоматическая доставка очереди во внешнее хранилище пока не настроена.

max_wal_size — цель для контрольных точек, а не жёсткая квота,
поэтому при восстановлении нужен дополнительный контроль диска.
См. [документацию PostgreSQL 17](https://www.postgresql.org/docs/17/runtime-config-wal.html#GUC-MAX-WAL-SIZE).

## Образы

PostgreSQL использует postgres:17-alpine. Для Python оставлен python:3.12-slim.
Образы API и бота исключают dev-зависимости и кеш установщика; при запуске uv не синхронизирует окружение.
Проверка работоспособности API использует стандартный Python, curl удалён из образа.

На одном Docker Engine Германии размер API уменьшился с 381 105 802 до 253 618 865 байт,
бота — с 302 385 101 до 202 648 708 байт. Это размер образов, а не RAM процессов.
После обновления проверены HTTP v2, дом без кодов и доступ настоящего токена тестового сообщества VK.
CI отдельно собирает оба минимальных образа и проверяет импорты рабочих модулей без dev-пакетов.
Геозапрос после обновления образов также прошёл: DaData ответила HTTP 200 через российский прокси,
поиск вернул адрес с кодами на v2.

В заключительном снимке API, бот и PostgreSQL занимали около 84, 53 и 61 МиБ RAM.
Свободный диск после переноса неизменяемой резервной копии во внешнее хранение — около 637 МиБ.
Это наблюдение после проверок, а не максимальный расход под любой нагрузкой.
