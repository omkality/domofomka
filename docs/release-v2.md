# Приёмка v2 и первый выпуск

**Кандидат проверен на dev; переключение prod требует отдельного разрешения владельца.**
В первый выпуск входит рабочий PostgreSQL с защищённым fallback v1.
OpenSearch остаётся локальным эталоном экспериментов и на VDS не устанавливается.

Весь цикл проходит на dev; выпуск prod требует отдельного разрешения владельца.

## Проверка безопасности перед выпуском

Аудит 9 ноября выявил уязвимые версии зависимостей и подвижные образы сборки.
Кандидат обновлён исправленными версиями в пределах прежних основных веток;
предыдущие результаты функциональной приёмки сами по себе не закрывали безопасность зависимостей.

- `certifi` обновлён до 2026.10.23; обновлены также отмеченные аудитом сетевые и серверные зависимости.
  Проверки OSV и PyPI не нашли известных уязвимостей в 39 зависимостях рабочего окружения.
  CI повторяет проверку экспортированного lockfile перед сборкой и деплоем.
- Python, uv, PostgreSQL и лабораторные образы OpenSearch закреплены версией и SHA-256 digest.
  CI использует Ubuntu 24.04, Python 3.12.16 и uv 0.13.7. Обновление закреплённых образов — явное изменение Git.
- API и бот запускаются с UID/GID 10001, без Linux capabilities и с запретом новых привилегий.
  Сохраняются корневая файловая система только для чтения, ограниченный `/tmp`, память, PID и ротация логов.
  В CI проверяется фактический процесс в собранном образе. Это не изменение SSH-пользователя или VPN.
- Файлы `codes.db`, каталога и индекса v1 должны читаться UID 10001; используются только read-only mounts.
  `.env` в образ не копируется и как файл приложению не монтируется. На dev права существующих данных
  позволяют чтение без изменения владельцев или разрешений. Сам контейнер PostgreSQL при этом не пересоздаётся.
- `SEARCH_CANDIDATE_LIMIT` применяется к рабочим читателям PostgreSQL/SQLite и их алиасам.
  Для упакованных улиц бюджет чтения составляет до десяти таких лимитов за проход.
  `SEARCH_MAX_QUERY_LENGTH` учитывается и API, и ботом. При прежних значениях все 416 полных записей
  замороженной свежей оценки совпали с принятым кандидатом; настройка ранжирования не менялась.
- Валидация конфигурации скрывает входные значения в текстах ошибок.
  Неиспользуемый `CACHE_EXPIRE_TIME` удалён; действующий ограниченный кеш поиска сохранён.
  Чтение TOML использует стандартный `tomllib`; SDK VK по-прежнему требует `requests`, собственные запросы — `httpx`.

Локально прошли 784 теста с настоящим PostgreSQL, один платформенный пропуск; предупреждения
устаревших объявлений параметров Litestar устранены явными `FromQuery`/`FromPath` без изменения URL.
Образы проверены в изолированной сети: UID, capabilities, запрет привилегий, read-only корень,
чтение смонтированных данных и HTTP-контроли. Повторена и изолированная репетиция отката v1.5.6.
Результат окончательного Linux CI и проверка Германии фиксируются в PR перед разрешением выпуска.

| Проверка | Критерий |
|---|---|
| Свежая выборка | Зафиксированы исходники, границы и разметка; результаты не используются для подстройки до завершения оценки |
| Правильность | Нет подтверждённых автоматических подмен явно заданных города, улицы, дома, корпуса и строения |
| Совместимость | Проверен прежний корпус; сохранность кандидатов не объявляется точностью ответа |
| Интерфейс | Текст, геометка, выбор, отмена выбора, пагинация подъездов, ограничения повторных нажатий |
| Отказы | Очередь и исходящие действия переживают перезапуск; сбой геолокации не блокирует новый текст |
| Маршрут | Отдельно проверены обычный прокси, прямой запрос и недоступный прокси с fallback |
| Ресурсы | Нагрузка ограничена; отсутствуют OOM, рост числа соединений и исчерпание диска |
| Копии | Проверено восстановление очереди и каталога; автоматические внешние копии и оповещения отменены владельцем |

Небольшая свежая выборка не доказывает универсальную точность. Запрос без города не позволяет
подтвердить, что угаданный город соответствует намерению. Исторический ответ v1 также не является эталоном.

## Итоговая приёмка 9 ноября

- До оценки заморожены код и данные; без подстройки обработаны 416 уникальных новых запросов
  из 85 диалогов. Все полные ответы PostgreSQL совпали с локальным контрольным каталогом.
  Для 100 текстов заранее размечены 96 номеров домов, 37 явно названных городов и семь номеров улиц;
  автоматических нарушений этих ограничений нет. Полная улица и намерение каждого пользователя
  в этой сотне независимо не размечены: это частичная проверка, не «100% точности».
- На всех 321 новых запросах, для которых v1 находил коды, полный прежний набор доступен в v2.
  Из них 298 получили адрес сразу, 23 — выбор адреса. Одноимённые города и отдельно сохранённые
  административные варианты не склеиваются ради улучшения метрики.
- Германия: ответы 100 свежих текстов совпали с локальным эталоном; дополнительно выполнены
  13 контролей дома/корпуса/строения и три независимых контроля полных кодовых наборов.
  Для 113 HTTP-запросов p50 около 19 мс, p95 344 мс, максимум 2,06 с.
  Это небольшая последовательная выборка с прогреваемыми кешами, не нагрузочный SLA.
- В шести реальных чтениях проверены VK и DaData: обычный прокси, прямой запрос и недоступный
  прокси с переходом напрямую. Трассы подтверждают использованный маршрут, а не только успешный ответ.
  Реальный геопоиск v2 вернул тот же адрес с кодами, что и следующий текстовый поиск.
  401/403 и исчерпание квоты проверены имитацией в тестах; лимит DaData не расходовался до отказа.
- На семи искусственных событиях в отдельной БД Германии проверены три ожидающих запроса на пользователя,
  интервал между ответами не меньше пяти секунд и сохранение ограничений после повторного открытия очереди.
  VK при этом не вызывался. Свежая копия очереди восстановлена в отдельную локальную БД без запуска бота;
  после проверки БД удалена, сам дамп очереди на ПК не сохранён.
- В изолированной сети повторена проверка отката v1.5.6 с настоящим Redis и подменённым вызовом VK.
  Старые исходники и окружение берутся из замороженной копии даже при изменении текущих файлов.
  Все 23 файла работающего prod только чтением сверены с опубликованным исходным снимком.
- Владелец подтвердил живую проверку dev-бота: адрес с подъездом, получение кода по кнопке,
  выбор и «Ни один из вариантов», геометка, затем новый текст. Браузерная автоматизация VK
  заблокирована политикой инструмента и не обходилась.
- Локально: 778 тестов и один платформенный пропуск. Linux CI: 779 тестов и
  [успешный деплой dev](https://github.com/omkality/domofomka/actions/runs/42593803848).
  Приложения проверены по SHA исходников; контейнер очереди сохранён, незавершённых заданий нет.

Для этого выпуска фиксируется принятый каталог `9d79c9fe…`. Шесть дополнительных предложений
привязки из [аудита](search-binding-resources.md) не применяются: исходные варианты и коды остаются
раздельными. Автоматизация оставшихся правил — [следующий цикл #12](https://github.com/omkality/domofomka/issues/12)
с отдельной полной регрессией. После выравнивания форматирования синтаксические деревья Python
и все 416 полных записей свежей оценки остались прежними.
Уже известные семь расхождений с историческим v1 не скрываются: шесть противоречат буквальному
адресу, одно содержит неподтверждённый суффикс города. Чужие коды ради совместимости не возвращаются.

[Машиночитаемые агрегаты](release-v2.summary.json) не содержат переписок, кодов, доступов или IP серверов.

## План первого переноса на prod

Операции установки ниже выполняются после отдельного разрешения владельца.
До него готовятся код, проверенный артефакт каталога и локальная репетиция.

1. Зафиксировать принятый dev-коммит и ревизию каталога. Подготовить стабильную версию `2.0.0`
   и тег после окончательной проверки; образы master собираются Actions заново с его SHA.
2. Повторно проверить объём диска и память Финляндии перед переносом; полный ГАР туда не копируется.
3. **До изменения исходного `.env`** установить приёмник из опубликованного комплекта Git
   с `--environment prod --legacy-v1-baseline`. Он проверяет 23 файла работающего v1.5.6
   по контрольным суммам `ops/legacy-v1-baseline.json`, сохраняет исходники, окружение и ID прежних образов.
   Redis сохраняется для отката, пока первый выпуск не принят. При несовпадении исходников установка останавливается.
4. Подготовить `.env` v2 для рабочего сообщества, выключить fault injection, сохранить параметры прокси.
   Включить аналитику с бюджетом 512 МиБ без удаления по возрасту.
   Поднять только PostgreSQL из опубликованного Compose, оставляя текущие приложения до переключения.
5. Подготовить отдельные PostgreSQL БД очереди/каталога и роль каталога только для чтения;
   сверить контрольные суммы кодов и происхождения записей с принятым снимком.
   Очередь prod создаётся пустой через однократную команду `src.vkbot.manage status` из нового образа;
   тестовая очередь Германии и её пользователи на prod не переносятся.
   Исходная `codes.db` v1 сохраняется, подготовленный индекс v1 подключается только для чтения.
6. Подготовить отдельные prod-секреты Actions. После разрешения владельца включить prod-деплой,
   подтвердить Environment и проверить текст, геометку, код по кнопке, диагностику, очередь и ресурсы.

Перенос на prod не входит в текущие испытания. Возврат к старой очереди автоматически не выполняется:
это способно повторить уже доставленные ответы. Каталог и очередь не восстанавливаются поверх работающих БД.

## Откат первого выпуска

Workflow `Rollback application` предлагает `previous` и отдельный `legacy-v1` для prod.
Второй вариант выбирает замороженный v1, даже если после первого выпуска уже были следующие обновления v2.
Одна исходная копия кода и окружения сохраняется отдельно от обычных двух поколений релизов;
снять её и Redis можно после принятия выпуска отдельным действием оператора.

Проверка v1 использует его `/version`, Redis и получение сервера Long Poll.
Проверка v2 использует каталог PostgreSQL и блокировку работающего сборщика.
Приложения останавливаются перед переключением; второй сборщик для рабочего сообщества не запускается.
Окружение и исходники v1 берутся из закрытого снимка, а зависимости — из прежних образов.
Синхронизация uv выключена, чтобы старый образ работал с файловой системой только для чтения.

PostgreSQL, каталог и очередь при откате на v1 сохраняются. Если осталась незавершённая работа v2,
повторный переход с v1 останавливается **до замены приложений**: сначала нужно сверить доставки,
поскольку v1 мог ответить пользователю за время отката. Слепой повтор исходящих действий недопустим.
Новые кнопки выбора адреса v2 старый бот не понимает; при аварийном откате адрес отправляется заново текстом.

Локальная репетиция использует настоящие образы v1.5.6 и Redis в изолированной сети.
Старый API прошёл проверку даже после изменения текущих исходников и `.env`: использован замороженный снимок.
Вызов VK подменён, внешняя сеть закрыта; реальный prod при этом не переключался.
Проверка Финляндии только чтением подтвердила совпадение всех 23 исходных файлов со снимком.

Каталог первого выпуска пересобран из окончательного принятого снимка: около 317,5 МиБ в формате `pg_dump`
и около 1,0 ГиБ после восстановления вместе с индексами. Дамп от 6 ноября устарел и не используется.
Новый дамп восстановлен в отдельную локальную БД при лимите PostgreSQL 192 МиБ;
для каждой таблицы проверены число строк и независимые от порядка контрольные суммы всех значений
относительно принятого файлового каталога, включая коды и происхождение.
Пять контрольных запросов прошли через роль только для чтения; создание объектов и запись в коды запрещены.
Проверочная БД и роль удалены. Этот артефакт нужен для однократного переноса, регулярных копий на ПК нет.

## Воспроизводимая проверка VDS

`tools/operations/dev_acceptance.py` запускается из опубликованного коммита на хосте dev с небольшим списком
запросов в JSON через stdin. Он читает API v1/v2, выполняет ограниченную смешанную нагрузку,
снимает память и проверяет реальные чтения VK/DaData через настроенный прокси, напрямую и после ошибки прокси.
В отчёте сохраняются фактические маршруты и статусы попыток без URL и реквизитов доступа.
Переопределения окружения действуют только для отдельного `docker exec`; рабочий бот не перенастраивается.
Отчёт содержит адреса и хранится только в игнорируемой папке `artifacts/private/`.
Это не браузерная проверка кликов и не имитация падения всех серверов.
