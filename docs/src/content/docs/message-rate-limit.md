---
title: "Ограничение частоты запросов"
---

Лимит привязан к паре «сообщество + пользователь». Запросы разных пользователей
не расходуют общий бюджет. Пока один пользователь ждёт, обработчик берёт задания других.
Общий технический лимит обращений к VK API продолжает работать отдельно.

## Настройки

| Переменная `.env` | По умолчанию | Поведение |
| --- | ---: | --- |
| `MESSAGE_RATE_BURST` | 2 | Два быстрых запроса проходят без ожидания лимитера. |
| `MESSAGE_RATE_INTERVAL_SECONDS` | 5 | Один токен восстанавливается за пять секунд. Ноль отключает входной лимитер. |
| `MESSAGE_HINT_INTERVAL_SECONDS` | 15 | Одинаковая подсказка о вводе адреса повторяется не чаще этого интервала после доставки. Ноль отключает подавление повторов. |

Проверка выполняется при выдаче задания из inbox, **до проверки подписки и поиска**.
Она охватывает новые текстовые запросы и геометки. Уже начатая попытка после сетевого
сбоя повторяется без повторного списания токена. Кнопки используют существующий отдельный
ограничитель нажатий пользователя. Состояние хранится в PostgreSQL и переживает перезапуск.

При исчерпании бюджета из ещё не начатых ожидающих запросов пользователя остаётся
последний. Например: два запроса прошли; затем быстро пришли три опечатки и исправленный
адрес — после восстановления токена обрабатывается исправленный адрес.
Заменённые задания получают причину `message_rate_coalesced`; их идентификаторы
сохраняются, чтобы сверка истории не вернула их в обработку.

Это ограничение частоты, а не оценка правильности запроса. Отсутствие дома в ГАР,
нулевой результат поиска, опечатка или транслитерация не являются поводом для блокировки.
Дополнительное сообщение «подождите» на каждую задержку не отправляется.
Время восстановления токена не включает ожидание воркера, поиск и доставку ответа.

## Повторные подсказки

Повтор одинакового текста «пришлите адрес» подавляется отдельно. Пока первая такая
подсказка ждёт отправки или повторяется после таймаута, её копии в outbox не добавляются.
После подтверждённой доставки выдерживается интервал из настройки.

Найденные адреса с кодами и ответы о конкретных домах без кодов не помечаются как подсказки
и этим механизмом не подавляются. Задержка входного лимитера при этом остаётся общей.

В диагностике отмечаются `message_rate_delayed`, `hint_suppressed` и причина объединения.
На пользователя добавляются две небольшие записи `bot_state`, без новых таблиц и сервисов.
Старые записи неактивного пользователя удаляются вместе с обслуживанием очереди.

## Кнопки и исходящие ответы

Входной бюджет текста не меняется: два быстрых запроса, затем один токен за пять секунд.
Для кнопок `ANTI_SPAM_TIME=2` задаёт паузу после подтверждённой доставки предыдущего действия;
`OUTBOX_PEER_MIN_INTERVAL_SECONDS=2` отдельно ограничивает отправки и редактирования одному пользователю.
Пока прежнее действие ожидает доставки или повтора, новые клики не запускают дополнительную работу,
даже если две секунды уже прошли. Пауза общая для всех видов кнопок одного пользователя.

Общий `VK_MIN_INTERVAL_SECONDS=0.4`, подтверждения нажатий раз в секунду, уведомления раз в десять
секунд и пауза при ошибках VK 6/9/29 сохраняются. Уменьшение пользовательской паузы не повышает
общую частоту HTTP-запросов и не обходит ограничения провайдера.
