Проект состоит из трёх частей: VK-бот, HTTP-сервис кодов и инфраструктура.
Версия API включает весь путь поиска, а не только URL маршрута.

## Структура кода

| Пакет или файл | Ответственность |
| --- | --- |
| `src/vkbot/` | Long Poll, восстановление истории, очередь, ограничение частоты, представление ответов и доставка в VK. Сервис кодов вызывается по HTTP. |
| `src/vkbot/processor.py`, `presentation.py`, `http.py` | Планирование/доставка, чистое оформление текста/клавиатур и транспорт VK разделены; RateGate находится рядом с HTTP-сессией. |
| `src/code_service/main.py` | Точка сборки Litestar: роутеры, зависимости, документация API, завершение работы. |
| `src/code_service/api/routes/` | Регистрация маршрутов. В `v1/codes.py` и `v2/codes.py` находятся только HTTP-обработчики; служебные пути — в `health.py`. |
| `src/code_service/api/http.py`, `api/diagnostics.py`, `api/dependencies.py` | Перевод ошибок в HTTP, диагностические ответы и зависимости обработчиков. |
| `src/code_service/services/geocoding.py` | Клиент DaData, общий для обеих версий. |
| `src/code_service/config.py` | Настройки сервиса кодов. Настройки бота остаются в `vkbot/config.py`. |
| `src/code_service/services/v1/` | Сценарии `search.py`, чтение SQLite `codes.py`, индекс `index.py`, сопоставление `matching.py`. |
| `src/code_service/services/v2/` | Сценарии `search.py`, разбор `normalize.py`, ограничения `constraints.py`/`localities.py`, общие правила ранжирования `ranking.py`, асинхронный PostgreSQL `postgres.py`, жизненный цикл читателя `catalog.py`, ограниченный кеш `cache.py`. Рабочий v2 имеет одно хранилище — PostgreSQL. |
| `tools/catalog/sqlite_catalog.py`, `async_reference.py`, `documents.py` | SQLite-эталон, адаптер офлайн-сравнений и экспорт документов для подготовки данных и тестов; не импортируются рабочими приложениями. |
| `src/infrastructure/` | Общие сетевые настройки, выбор прямого/прокси-маршрута, измерение этапов и версия приложения. Без зависимостей от бота или сервиса кодов. |
| `ops/` | Инфраструктура хоста: приём выпуска, развёртывание, откат и контроль хранения. Эти скрипты работают вне приложений. |
| `src/infrastructure/database/` | SQL-миграции yoyo, проверка совместимости схемы и SQL-ресурсы. Обычный worker не загружает и не запускает yoyo. |
| `ops/config/`, `ops/systemd/` | Декларативные конфиги штатных средств ОС и systemd units; установщик не генерирует их синтаксис. |
| `tests/unit/`, `tests/integration/`, `tests/fixtures/` | Правила и сценарии, реальные границы компонентов, общие изолированные ресурсы тестов. |
| `tools/` | Отдельные команды подготовки каталога, аудита переписок, оценки поиска, экспериментов и операций. [Порядок запуска](../../../../tools/README.md). |

Роуты принимают параметры и вызывают сценарий. В них нет SQL или ранжирования.
Сценарии и читатели не зависят от Litestar. v1 не импортирует v2; v2 явно вызывает
v1 только для проверенного fallback. Бот не импортирует внутренности сервиса кодов.
Эти границы проверяются тестами по AST всех модулей, включая запрет обратных зависимостей.

## HTTP-контракт

| Операция | Основной путь | Совместимые пути |
| --- | --- | --- |
| Текст v1 | `GET /api/v1/codes?address=...` | `/api/v1/codes/msg?message=...`, `/codes/msg?message=...` |
| Текст v2 | `GET /api/v2/codes?address=...` | `/api/v2/codes/msg?message=...` |
| Геопоиск v1 | `GET /api/v1/codes/nearby?lat=...&lon=...` | `/api/v1/codes/geo`, `/codes/geo`, `/codes/nearby` |
| Геопоиск v2 | `GET /api/v2/codes/nearby?lat=...&lon=...` | `/api/v2/codes/geo` |
| Выбранный дом v2 | `GET /api/v2/buildings/{building_id}` | — |

Совместимые геопути принимают те же `lat`/`lon`. Параметр `observe=true` включает диагностику
для бота. GET поиска возвращает результат, в том числе `not_found`/`no_codes`, в теле ответа;
отсутствующий ID дома даёт 404, недоступность геокодера или чтения выбранного дома — 503.
POST к коллекции кодов не поддержан и возвращает 405. Документация OpenAPI доступна по `/docs`.

Текст и геометка v2 после определения адреса проходят один сценарий поиска. Проверенный fallback
сохраняет ограничения явно указанного города, улицы, дома, корпуса и буквы. Геокодирование не
подменяет отсутствующий дом соседним ради выдачи кодов.

## Запуск и маршрутизация

Granian загружает `src.code_service.main:app`. Функция `create_app()` подключает
зависимости, список из `api.routes.route_handlers()` и завершение читателя каталога.
Регистрация связывает версию HTTP-маршрута с одноимённым пакетом сервисов:
`api/routes/v2/codes.py` вызывает `services/v2/search.py`, v1 — соответствующий сценарий v1.
Совместимые URL регистрируются явно, без копирования алгоритма поиска.

Бот запускается как `python -m src.vkbot.main`: точка входа создаёт `Runtime`, который
управляет сбором событий, обработчиками, доставкой и обслуживанием.

## Развёртывание

Перед запуском нового бота отдельный одноразовый контейнер применяет ожидающие
миграции под блокировкой yoyo. Приложения проверяют ревизию и не исполняют DDL при старте.

Readiness CI/CD проверяет HTTP-ответ именно v2: работающий fallback не маскирует
отказ каталога. При запуске обновления каталога механизм развёртывания выбирает
модуль внутри образа по его фактической структуре. Это позволяет откатываться на уже выпущенные образы.
Контрольные суммы замороженного prod v1 в `ops/legacy-v1-baseline.json` не меняются.

[Схема БД](database.mdx), [доставка сообщений](message-delivery.mdx), [CI/CD](cicd.mdx).
Разработка и приёмка выполняются на dev. Выпуск prod требует отдельного решения владельца.
