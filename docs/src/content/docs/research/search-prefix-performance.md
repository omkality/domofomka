## Сокращённый город: спросить вместо угадывания

Восстановлены 11 разных текстов, отклонённых последней защитой fallback: десять исторических
и одна гипотеза исправления. При полном названии улицы и точном доме оставшаяся часть запроса
может быть префиксом города длиной от четырёх букв. Полное известное название города не считается
префиксом другого города. Буква дома, корпус, строение и номер улицы сохраняют точные ограничения.

Результат такого восстановления — **уточнение с кнопкой даже при одном варианте**. Предлагаются
только адреса с кодами; город не дописывается автоматически. У пользователя остаётся кнопка
«Ни один не подходит». Неполное название улицы этим правилом не расширяется.

одинаковые исходники, снимок каталога и настройки индекса. Ошибок движка и конфликтов ручных
ограничений нет. После архитектурного рефакторинга все поисковые результаты совпали с `135522b`.

Сравнение уникальных наборов «подъезд, источник, код» охватывает 41 918 разных текстов.

города. Это проверка совместимости, а не доказательство правильного намерения пользователя.
Набор, доступный через несколько вариантов меню, не считается автоматически отправленным.

Native остаётся лабораторным кандидатом. В расширенном пилоте из 1 615 записей сохранены
500/500 исторических и 65/65 подсказок прежних потерь. На 453 предполагаемых опечатках — 381
подсказка у каталога и 452 у native; в 399 ограничениях адреса конфликтов нет. На полном корпусе
у native остаются 23 сужения набора относительно прежнего каталога из-за различий полных
и неподтверждённых длинных имён. Правило выбора по неполному имени ещё требует принятия.

## Пакетное чтение каталога и пределы VDS

Чтение упакованных домов больше не делает два SQL-запроса для каждой найденной улицы.
Метаданные и упакованные номера читаются одной пачкой; порядок и адресные ID сохраняются.

Локальные парные измерения на одинаковых данных, три повтора с чередованием порядка:

| Широкий запрос | SQL до → после | Время до, мс | Время после, мс |
| --- | ---: | --- | --- |
| A | 4 009 → 11 | 3 535 / 3 455 / 3 792 | 494 / 537 / 560 |
| B | 4 008 → 10 | 3 276 / 3 134 / 3 081 | 219 / 201 / 220 |

Результаты равны. Пик выделений Python по `tracemalloc` — 12,8 МиБ, это **не общий RSS**.
Кеш ОС не очищался, параллельно работала лаборатория: времена не являются SLA сервера.
400 полных ответов рабочего PostgreSQL-клиента совпали с файловым каталогом без кеша результатов;
локально PostgreSQL p50 11,617 мс, p95 41,027 мс.

**Два широких запроса на VDS всё ещё достигают двухсекундного statement timeout** при выборе
кандидатов из полного каталога. Пакетное чтение устранило лишние SQL-обращения, но не стоимость
основного чтения с диска. Изолированный диагностический EXPLAIN с увеличенным только для него
таймаутом показал около 5,2 с с двумя параллельными работниками и 7,3 с без них. Увеличение
рабочего таймаута и памяти не внедрялось; отключать параллелизм по этому опыту хуже.

На dev проверен 41 HTTP-поиск и 16 ответов выбранных домов. Адреса, варианты выбора и коды
совпали. В двух полных ответах отличается только причина fallback: VDS получил таймаут,
локальный каталог — `not_found`. Это открытая задача стоимости запроса, не ошибка сети VK.

## Геолокация и недоступность DaData

Пять обычных обращений к DaData проверили Москву, Подмосковье и Петербург, включая отдельное
уточнение ответа провайдера. Московская точка дала `found`, подмосковная — `no_codes`.
Одна петербургская точка не дала полного дома; другая определилась, но точного дома нет в каталоге.
Геопоиск там дал `not_found`, как и тот же адрес текстом. Соседний дом с кодами не подставлялся.
Это проверка геокодирования, а не успешной выдачи петербургских кодов.

После определения адреса геометка v2 проходит тот же поиск и проверенный fallback v1, что и текст.
Исправлено форматирование неполных полей DaData: населённый пункт при отсутствии `city`, обязательный
номер дома, отсутствие выдуманного типа корпуса/строения.

По [документации DaData](https://dadata.ru/api/suggest/address/) 403 может означать суточный лимит,
ключ или неподтверждённую почту; 429 — ограничение частоты. Поэтому для 401/403 бот сообщает
об общей временной недоступности геоопределения и предлагает текст, не заявляя точную причину.
Такая задача не создаёт отложенных геоповторов. Защита API на
`DADATA_ACCESS_COOLDOWN_SECONDS` (по умолчанию 3 600 с) прекращает повторные обращения этого процесса.
Она сбрасывается после перезапуска; это не вычисление полуночи у провайдера. Ошибки доступа не
переключают прокси/прямой маршрут. Обычный сетевой сбой сохраняет прежний отложенный повтор.

Квоту не исчерпывали. В изолированном процессе образа dev два имитированных отказа дали HTTP 503
с `geocoding_retryable=false`, а подставной транспорт был вызван один раз. Затем текст нашёл адрес.
В этом тесте не было внешних запросов DaData и изменений работающего процесса API.

## Архитектура и проверка доставки

[HTTP, сценарии и адаптеры разделены](../architecture.mdx). Прежние URL сохранены, добавлены основные
GET-пути коллекции кодов и геопоиска. Полный прогон Linux CI: **712 прошли**; локально Windows:
711 прошли, одна проверка пропущена. Тесты проверяют новые и совместимые пути, HTTP-ошибки
геокодирования с диагностикой и без неё, корпуса/буквы и неизменность v1.

Проверка на тестовом боте использовала только владельца: уточнение сокращённого города,
выбор дома и подъезда дали одну отправку и два редактирования; все три операции приняты VK,
аналитика записана. Внешних вызовов DaData не было. Визуальный индикатор клиента VK в этом тесте
не проверялся, массовой рассылки не было.
