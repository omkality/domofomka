Москва, Подмосковье и Петербург не ограничивают географию поиска. Частота запросов
нужна для разрезов качества, а не для подстановки города вместо пользователя.
Рабочий алгоритм не менялся; native OpenSearch остаётся локальным экспериментом.

## Исходные данные

Проверены все 2 282 диалога сохранённой выгрузки: 198 060 сообщений,
84 488 входящих непустых текстов. Список диалогов получен 6 ноября в 01:23 МСК,
последнее входящее сообщение снимка — в 01:42 МСК. Это полный сохранённый снимок,
а не повторная выгрузка актуальной переписки на 8 ноября.

Названия извлечены потоково из 96 файлов `AS_ADDR_OBJ` ГАР: 160 340 действующих
объектов уровня населённых пунктов, включая города федерального значения.
Учитываются целые слова, длинные названия, явные пометки и существующие алиасы
`мск`, `спб`, `питер`. Словарь не исправляет опечатки и не использует нормализатор
проверяемого поиска. Числовое название посёлка без однозначной пометки
не превращает номер дома в упоминание населённого пункта.

Лексические совпадения найдены в 27 835 текстах; 56 653 текста не содержат
таких признаков. Всего наблюдаются 342 названия, из них 195 имеют тип города
в ГАР. **Это не 195 достоверно установленных городов назначения.** Например,
«Волжский бульвар» содержит название города, но обозначает улицу. Контекст улицы
отмечается отдельно; совпадение с названием улицы сохраняет неопределённость.
В 1 606 текстах встречается несколько названий. Строки таблицы могут пересекаться.

## Сравнение поиска

Прежний полный прогон 46 908 случаев / 93 816 ответов повторно разложен по
упоминаниям во входном тексте. Перед повторным использованием проверены SHA-256
каталога и совпадение всех 34 исходных файлов алгоритмов. Все ответы учтены,
включая 31 471 запрос без признака населённого пункта и 849 с несколькими названиями.
Сохранность исторических подсказок по всему корпусу одинакова у обоих вариантов:
44 002 из 44 083. Это совместимость, а не измерение правильности намерения.

Дополнительно выбраны 943 различных текста из прежних отказов/отсутствия ближайшего
ответа: не более восьми на каждую из 257 подходящих групп названий. Включены редкие
группы и запросы без номера дома; уже проверенные тексты исключены. Пунктуация,
дроби, буквы, корпуса и строения сохраняются при удалении повторов.
Выборка равномерная по группам, а не пропорциональная трафику.
Это не 257 подтверждённых городов: неоднозначные имена остаются признаками.

| Результат | Текущий каталог | Native OpenSearch |
|---|---:|---:|

| `no_codes` | 463 | 463 |
| `no_codes_ambiguous` | 64 | 62 |
| `not_found` | 264 | 256 |
| `incomplete_query` | 84 | 85 |
| `invalid_query` | 0 | 1 |

Native: `verified.coverage-AUTO-r1.0`, OpenSearch 3.3.2, индекс улиц с кодами,
BM25 `b=0.2`. Оба варианта используют тот же снимок каталога и проверенный fallback v1.
Дополнительный прогон локальный: 1 886 ответов. Задержки и настройки сохранены
в [сводке](../../../../search-locality-coverage.summary.json); это не измерения VK или VDS.

У десяти запросов расходится статус или адрес. Разобраны также 29 запросов,
у которых название из текста не входит в город/иерархию найденного дома:
многие обозначают улицу, ЖК либо старое представление источника, поэтому само
несовпадение ещё не ошибка. Подтверждены **два нарушения населённого пункта у native**:
явный посёлок заменён улицей другого города; указанный город с микрорайоном
заменён созвучным микрорайоном другого города. Текущий каталог в обоих случаях
возвращает `not_found`. Полные тексты и ручные заключения сохранены закрыто.

Число `found` нельзя объявлять качеством. Автоматический счётчик конфликтов
для неразмеченных примеров равен нулю, но не проверяет намерение и не заменяет
эту ручную проверку. Старый «Нет результатов» тоже не доказывает, что кодов нет.

Дополнительно 38 запросов из разных групп сверены с настоящим API dev на Германии:
совпали полные JSON-ответы с локальным приложением, включая fallback и данные кодов.
VK и DaData в этой проверке не вызываются. PostgreSQL и каталог на dev не менялись.
Полный локальный набор с настоящим PostgreSQL: 743 теста прошли, один пропущен
на Windows; линтер не нашёл ошибок. Новые 15 тестов проверяют сам аудит и выборку.

## Воспроизведение

Исходные данные остаются в игнорируемом `artifacts/private`; доступы, тексты
переписки, идентификаторы пользователей и коды не публикуются. Открыты только
агрегаты и контрольные суммы. Каталог: `9d79c9fe…c8ec0a`.

```powershell
python -m tools.history.audit_query_localities --output artifacts/private/locality-audit-new
python -m tools.history.build_locality_cohort --audit artifacts/private/locality-audit-new --frozen artifacts/private/prefix-performance-20261107/full-architecture-core --output artifacts/private/locality-cohort-new
python -m tools.experiments.benchmark_native_search run --catalog artifacts/search/serving.source-fields-final.db --stage lexical --index domofomka-native-lab-20261107-coded-b02 --variants catalog,verified.coverage-AUTO-r1.0 --case-file artifacts/private/locality-cohort-new/cases.jsonl --output artifacts/private/locality-cohort-new/replay --details --workers 4
```

[Продолжение эксперимента](search-locality-guard.md) сравнивает варианты защиты
на 47 857 записях. Широкое ограничение отклонено из-за потерь; узкое устраняет
две подмены без дополнительных потерь кодовых наборов. Опечатки в городах,
неполные имена и размещение JVM остаются отдельными проверками.
Native не внедряется, выпуск и prod остаются приостановлены.
