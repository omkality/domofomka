Штатные политики journald, logrotate, APT и systemd хранятся в `ops/config/` и `ops/systemd/`.
`ops/host_storage.py` устанавливает эти файлы, проверяет синтаксис и сохраняет предыдущую конфигурацию.
Перед изменениями сохраняются три последних набора конфигурации в закрытой папке `/var/backups/domofomka-storage`.
Изменения не затрагивают пароли root, SSH, VPN, порты и маршруты.

| Источник роста | Ограничение |
|---|---|
| systemd journal | 64 МиБ на диске, файл до 8 МиБ, срок 7 дней; резерв свободного места 512 МиБ |
| Журналы авторизаций и syslog | Проверка logrotate каждые 5 минут, maxsize 2 МиБ, до 7 архивов |
| btmp / wtmp | 2 МиБ × 7 и 1 МиБ × 2; активный файл может вырасти между проверками |
| Tinyproxy | maxsize 1 МиБ, 4 архива, copytruncate без reload прокси |
| Кэш пакетов | APT периодически ограничивает возраст и объём |
| Core dump | Большие дампы не сохраняются; для новых контейнеров domofomka дополнительно core=0 |
| API и бот dev | Корневая файловая система read-only, временный /tmp ограничен 16 МиБ RAM |
| Docker-логи domofomka | Существующие ограничения 10 МиБ × 3 файла на контейнер |
| Резервные копии очереди на dev | Не более трёх дампов, проверка свободного места до создания |

Amnezia не пересоздаётся и не перенастраивается. VPN-контейнеры сохраняют собственные настройки журналирования.
У старого немецкого `amnezia-socks5proxy` Docker-лимит не задан; по решению владельца его конфигурация сохранена.
Настройка Docker не позволяет навязать новый log-лимит уже созданному контейнеру без пересоздания.
Проверка размера журнала сама по себе не доказывает наличие или отсутствие внутренней ротации приложения.

## Аварийная защита хоста

`domofomka-disk-reserve.timer` проверяет место раз в минуту. По умолчанию:

- при достаточном месте заранее выделяется физический резерв 256 МиБ;
- ниже 512 МиБ свободного места резерв освобождается и запускается штатная очистка журналов/кэша;
- если после очистки остаётся меньше 128 МиБ, останавливаются только контейнеры domofomka;
  VPN, SSH и неизвестные сервисы не останавливаются;
- резерв создаётся заново только при свободных 1,25 ГиБ, чтобы избежать постоянного выделения и освобождения;
- остановленные приложения сами не перезапускаются: сначала нужно устранить причину нехватки места.

Пороги находятся в `/etc/domofomka-storage.env`. У службы ограничены CPU, память и время выполнения.
Это периодическая аварийная защита; строгая изоляция объёма произвольного root-процесса требует отдельных
файловых систем/квот. Разметка дисков не менялась. Скрипт не выполняет глобальный Docker prune,
не удаляет БД, образы или произвольные файлы пользователя. Оповещения наружу отключены по решению владельца.

## Данные бота и размеры

- Завершённые задания и ответы: 180 дней; незавершённые задания не удаляются по возрасту.
- Контекст кнопок: 90 дней; контекст незавершённого диалога сохраняется.
- Диагностика: расчётный бюджет 512 МиБ на сообщество, без удаления по возрасту.
- При заполнении бюджета удаляется необходимое число самых старых диагностических записей завершённых запросов.
  Их этапы/сетевые попытки удаляются каскадно. Очередь и коды домов при этом не удаляются.
- Если всю диагностику занимают незавершённые задания, новые измерения могут быть пропущены;
  обработка запросов продолжается. Заполнение диагностики не должно блокировать очередь.

Бюджет аналитики дополнительно начисляет 2 КБ на этап, учитывая SQL-строки и индексы консервативно.
Поэтому 512 МиБ — расчётный бюджет живых записей, а не квота на файл PostgreSQL.
При небольшом объёме старая аналитика сохраняется; после освобождения места PostgreSQL использует его повторно.
Удаление SQL-строк освобождает место для повторного использования PostgreSQL; файл БД обычно сразу не уменьшается.

## Резервирование

Регулярных копий на ПК нет.
На dev остаются максимум три дампа очереди, с резервом места перед созданием; передавать их куда-либо автоматически не нужно.
Копии на том же сервере не защищают от потери его диска. Оповещения наружу не включены.

Проверка службы хранения: `systemctl status domofomka-disk-reserve.timer logrotate.timer` и `journalctl --disk-usage`.
