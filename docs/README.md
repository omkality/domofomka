# Документация domofomka

Статическая русскоязычная вики: Astro/Starlight и интерактивные схемы LikeC4.
Публичный сайт: **https://omkality.github.io/domofomka/**.
Исходники статей находятся в `src/content/docs`, модель — в `architecture/*.c4`.
Исторические JSON/CSV-отчёты остаются в корне `docs`: их пути используют команды оценки.

Требуется Node.js 22.23.4 или новее. Из каталога `docs`:

```bash
npm ci
npm run dev
```

Astro откроет локальный сайт на `http://127.0.0.1:4321` и обновляет его при изменении
статей и C4-модели. Процесс работает только пока запущена команда; остановка — `Ctrl+C`.
Docker и nginx для документации не используются.

Для проверки готовой статической сборки:

```bash
npm run build
npm run preview
```

`preview` раздаёт каталог `dist` через Astro на том же локальном адресе.

`npm run build` проверяет модель, ссылки, якоря и наличие статических ресурсов,
собирает HTML/CSS/JS в `dist` и ограничивает размер
результата 32 МиБ. CI собирает и сохраняет сайт отдельным артефактом. Node, npm,
LikeC4 и исходники вики не включаются в образы бота и API и не нужны на VDS.
Готовый `dist` можно раздавать любым статическим хостингом. Для подкаталога задайте
`DOCS_BASE_PATH=/domofomka`, для абсолютных ссылок — `DOCS_SITE_URL`.

После push в `dev` тот же проверенный сайт автоматически публикуется на GitHub Pages.
Сборка использует `DOCS_BASE_PATH=/domofomka` и `DOCS_SITE_URL=https://omkality.github.io`.
Pull request проверяет документацию без публикации. Environment `github-pages`
допускает только ветку `dev`; права записи Pages и OIDC выданы только задаче публикации.
Публичный хостинг не требует контейнера или диска на VDS; локальный просмотр остаётся доступен.

После изменения процессов обновите соответствующие статьи и C4-модель, затем
выполните сборку. Данные пользователей, `.env`, дампы и адреса серверов в вики не публикуются.
Правило обновлять документацию вместе с кодом закреплено в [AGENTS.md](../AGENTS.md).
